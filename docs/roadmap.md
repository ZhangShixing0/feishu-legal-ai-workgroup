# 项目路线图

路线图以“降低错误交接和未复核文书的概率”为主线，不以无人化替代律师为目标。

## V1：可用的两步工作群（当前）

- [x] 两个独立飞书 AI 员工进入同一内部群。
- [x] ZIP + XLSX 收集、材料提取、缺失/冲突提示。
- [x] 第一阶段核对页与 Excel 生成门槛。
- [x] 起诉信息补充页与固定模板 Word 生成。
- [x] SQLite 案件状态、事件去重和审计记录。
- [x] 飞书 REST 重试、幂等和卡片重发恢复。
- [x] 匿名化示例、发布安全审计和 CI 基线。

V1 明确限制：单群同一时间只有一个活动案件；只支持一种金融借款合同纠纷模板；不承诺对扫描件和复杂版式材料做到完全自动识别。

## V1.1：可靠运行

目标：让系统在网络波动、进程重启和多人连续提交时仍可恢复。

- 多案件显式队列与案件选择器。
- 任务租约、超时恢复和可安全重试的后台作业。
- 运维状态页、失败步骤定位和一键重发。
- 结构化审计导出与案件级操作时间线。
- Windows 与 Linux 的统一启动、停止和升级脚本。

验收指标：重复事件不产生重复文书；服务重启后活动案件可恢复；每个失败都能定位到明确步骤。

## V1.2：安全与治理

目标：达到律所内部小范围生产试用的治理要求。

- 用户与角色授权、案件级访问控制。
- 数据留存、自动清理、备份恢复和密钥轮换流程。
- 静态数据加密与敏感日志脱敏。
- 模板版本、字段规则版本和生成结果可追溯。
- 依赖漏洞检查、发布签名和最小权限部署基线。

验收指标：任何生成文件都能追溯到模板、字段快照、操作者和时间；过期数据可验证删除。

## V2：多模板与批量能力

- 模板注册、字段模型和规则配置化。
- 多类案由与多版本法院表单。
- Excel 批量案件队列和批次级进度。
- 证据目录、送达地址确认书等配套文书。
- 模板长度、分页和字体回归基线。

验收指标：新增模板不需要修改核心编排代码；每个模板都有独立测试夹具与版式基线。

## V3：可评测的模型辅助

- OCR/规则/模型多路抽取与来源定位。
- 字段级置信度、冲突解释和人工确认门槛。
- 匿名化评测集、准确率/召回率和错误类型看板。
- 人工修正反馈闭环，但不直接使用未经授权的客户数据训练。

验收指标：模型建议必须带来源；低置信度字段不得自动进入最终文书；版本升级可量化比较。

## 暂不纳入

- 无人审查直接提交法院。
- 机器人自主决定诉讼请求、利息口径或证据取舍。
- 在未完成权限和留存治理前面向外部客户开放。
- 用真实案件数据作为公开演示或开源测试集。
