# 安全说明

## 安全结论

本项目处理身份证、联系方式、借款合同、账户信息和诉讼材料，默认应按高敏感法律业务数据管理。飞书群聊不是天然的数据泄露点，但它扩大了数据接触面：平台存储、群成员、机器人权限、链接转发和服务器下载目录都成为安全边界的一部分。

## 两种运行模式

| 模式 | 数据路径 | 适用场景 | 主要风险 |
| --- | --- | --- | --- |
| 本地模式 | 浏览器 ↔ 本机服务 | 单机验证、模板调试 | 本机账户和磁盘安全 |
| 飞书工作群 | 飞书内部群 ↔ 律所服务器 ↔ 飞书群 | 团队协作 | 群成员范围、平台留存、机器人权限、外链和服务器运维 |

电脑关机后，本地模式和本地运行的机器人都会离线。持续服务必须部署到受控、常开的服务器。

## 数据分类

- **最高敏感**：身份证影像、身份证号、借款合同、银行账户、征信或催收材料。
- **高敏感**：姓名、电话、住址、欠款金额、诉讼策略、生成文书。
- **机密配置**：飞书 App Secret、服务器凭证、访问令牌、Basic Auth 文件。
- **可公开**：已匿名化的代码、文档、虚构测试数据和清除元数据后的模板。

## 强制控制

### Git 与协作

- 不提交 `.env.feishu`、`tmp/`、`outputs/`、`work/`、`feishu_workgroup/data/`。
- 不在 Issue、PR、CI 日志或截图中使用真实案件材料。
- 提交前运行 `python tools/release_audit.py`。
- 若密钥进入聊天、日志或 Git 历史，应立即轮换；仅删除文件不足以撤销泄露。

### 飞书

- 两个机器人都只发布到本企业，禁止外部租户使用。
- 案件群关闭外部成员，并定期复核成员名单。
- 正式使用前必须设置 `FEISHU_ALLOWED_CHAT_IDS`。
- 材料专员才需要接收群消息和下载文件；诉状专员保持更小权限。
- 随机补充链接不得转发，反向代理不得记录完整查询令牌。

### 服务器

- Python 服务仅监听 `127.0.0.1`，不直接开放 8765/8777/8788。
- 使用 HTTPS、访问认证、防火墙和最小权限 systemd 账户。
- `.env.feishu` 权限建议为 `0600`；运行目录建议 `UMask=0077`。
- 数据目录与系统目录分离，并配置加密磁盘、备份策略和最短必要留存期。
- 定期安装操作系统、Nginx、Python 依赖和 OCR 组件安全更新。

## 上线清单

- [ ] 已轮换体验阶段使用过的 App Secret。
- [ ] 群里没有外部成员，机器人可用范围已限制。
- [ ] `FEISHU_ALLOWED_CHAT_IDS` 已配置。
- [ ] 服务器只开放 80/443，三个应用端口仅回环监听。
- [ ] HTTPS 证书、访问认证和安全响应头有效。
- [ ] 已定义文件和 SQLite 的留存与清理周期。
- [ ] 已验证备份恢复与密钥轮换流程。
- [ ] 已运行全量测试和发布安全审计。
- [ ] 已由律师确认模板、字段映射、诉讼请求和提示语。

## 事件响应

1. 立即停止相关机器人或撤销应用版本。
2. 轮换飞书 Secret、访问密码和可能受影响的服务器凭证。
3. 保留必要审计记录，确认受影响案件、群和时间窗口。
4. 删除不必要副本，并按组织制度评估通知、报告和补救义务。
5. 修复根因后，在隔离环境回归测试，再恢复服务。

安全问题请通过仓库所有者的私密渠道报告，不要在公开 Issue 中附带利用细节、凭证或案件样本。另见根目录 [SECURITY.md](../SECURITY.md)。
